# Quantum-chemistry tensor kernels

This directory contains small, self-contained `Problem` files for exercising
Truthmill on realistic tensor algebra. They are equation kernels, not complete
electronic-structure programs: orbital generation, integral transformation,
amplitude iteration, eigensolvers, and convergence control are outside the
model.

## Common conventions

- Domain `0` is the occupied orbital space `O`, with example size 1000.
- Domain `1` is the virtual orbital space `V`, with example size 5000.
- `i` through `n` denote `O`; `a` through `f` denote `V` in the descriptions
  below. These names are documentation only. JSON stores local integer index
  IDs and their domains.
- The sizes are illustrative cost parameters. They may be changed without
  changing the formal tensor identities.
- Coefficients are exact rationals serialized as `[numerator, denominator]`.
- A reciprocal denominator such as `D2` or `D3` is an opaque input tensor.
  Truthmill neither constructs it from orbital energies nor assumes identities
  beyond its declared permutation symmetry.
- The reference programs are direct, equation-oriented translations. They are
  intentionally not optimized and are useful as optimizer inputs and verifier
  baselines.

Tensor IDs are local to each file:

| File | Tensor IDs | Outputs, in order |
| --- | --- | --- |
| `mp3.json` | `0 = g[p,q,r,s]`, `1 = D2[a,b,i,j]` | third-order correlation energy `E3` |
| `ccd.json` | `0 = f[p,q]`, `1 = g[p,q,r,s]`, `2 = t2[a,b,i,j]` | correlation energy, doubles residual `R2[a,b,i,j]` |
| `ccsd.json` | `0 = f`, `1 = g`, `2 = t1[a,i]`, `3 = t2[a,b,i,j]` | correlation energy, singles residual `R1[a,i]`, doubles residual `R2[a,b,i,j]` |
| `ccsd_t.json` | `0 = g`, `1 = t1`, `2 = t2`, `3 = D3[a,b,c,i,j,k]` | perturbative triples correction `E(T)` |
| `eom_ccsd.json` | `0 = f`, `1 = g`, `2 = t1`, `3 = t2`, `4 = r1[a,i]`, `5 = r2[a,b,i,j]` | `sigma1[a,i]`, `sigma2[a,b,i,j]` |
| `adc2.json` | `0 = f`, `1 = g`, `2 = t2^(1)[i,j,a,b]`, `3 = r1[i,a]`, `4 = r2[i,j,a,b]` | `sigma1[i,a]`, `sigma2[i,j,a,b]` |
| `ccsd_lambda.json` | `0 = f`, `1 = g`, `2 = t1`, `3 = t2`, `4 = l1[i,a]`, `5 = l2[i,j,a,b]` | Lambda singles residual, Lambda doubles residual |

Here `f` and `g` are used through multiple occupied/virtual blocks, so their
displayed `p`, `q`, `r`, and `s` axes mean general orbitals. The current
Truthmill model infers rank but does not declare a fixed domain for each tensor
axis; each access records its domains in the operation's `Code`.

## What each problem represents

`ccsd.json` is the full spin-orbital CCSD correlation-energy, singles-residual,
and doubles-residual kernel generated from the published Drudge coupled-cluster
generator. `ccd.json` is generated by the same code with a doubles-only cluster;
it is also the exact `t1 = 0` specialization of CCSD, with the singles equation
omitted. The two-electron integrals and doubles amplitudes declare separate
antisymmetry in their two particle and two hole slots.

`eom_ccsd.json` is the directional derivative of the CCSD singles and doubles
residuals in the direction `(r1, r2)`. It is therefore the EE-EOM-CCSD
Jacobian-vector product, before subtracting an eigenvalue times the trial
vector.

`mp3.json` uses canonical-Hartree-Fock, normal-ordered spin-orbital equations.
It forms first-order doubles, the connected second-order doubles numerator,
second-order doubles, and finally `E3`. The disconnected first-order-energy
term is absent because it cancels the corresponding term in the projected
second-order amplitude equation.

`ccsd_t.json` follows the spin-orbital p-dagger-q example: it forms the
connected triples numerator at `t3 = 0`, multiplies it by the supplied `D3`,
and contracts the result with `g`, `t1`, and `t2`. As in that example, the left
singles and doubles used by the energy expression are the transposes of `t1`
and `t2`; they are not independent Lambda inputs.

`ccsd_lambda.json` contains the CCSD Lambda singles and doubles residuals. It
keeps `l1` and `l2` as independent inputs.

`adc2.json` is the non-CVS particle-propagator ADC(2) matrix-vector kernel with
the standard block orders `ph_ph = 2`, `ph_pphh = 1`, `pphh_ph = 1`, and
`pphh_pphh = 0`. Symmetrization and antisymmetrization from the source equations
are expanded into explicit `LinComb` nodes. Its input tensors deliberately have
no declared permutation symmetry: this is conservative and avoids confusing
the spatial-orbital storage convention with the spin-orbital convention used by
the coupled-cluster examples.

## Provenance and present limits

- CCD and CCSD are direct exports of the algorithm in the upstream Drudge
  `docs/examples/gencc.py` at commit
  [`abb1e982`](https://github.com/DrudgeCAS/drudge/blob/abb1e982f2172dae68e3d6b3c5fe991da2518037/docs/examples/gencc.py).
  EOM-CCSD is the exact directional derivative of that exported CCSD residual.
- The upstream
  [Gristmill repository](https://github.com/DrudgeCAS/gristmill/tree/dc4c07205b9a4d696227402f43e9e1e36083d16e)
  owns tensor optimization and code generation. Its default branch is named
  `master`, not `main`, and currently contains selected CC optimizer examples
  rather than a full CCSD equation generator. Symbolic construction of the
  equations is provided by the companion Drudge repository.
- MP3 follows the DePrince Lab many-body perturbation theory derivation:
  <https://www.chem.fsu.edu/~deprince/tutorials/jupyter_notebooks/mbpt/mbpt.html>
- CCSD(T) and CCSD Lambda follow the generated spin-orbital examples in
  p-dagger-q:
  <https://github.com/edeprince3/pdaggerq/tree/master/examples/full_cc_codes>
- ADC(2) follows the matrix blocks and intermediates in adcc:
  <https://github.com/adc-connect/adcc/blob/master/adcc/adc_pp/matrix.py>

The integration tests establish that every file deserializes, validates, can be
scored, and survives Truthmill's exact canonicalization pipeline. They do not
yet constitute an independent numerical cross-check against a quantum-chemistry
implementation. Adding small numerical oracle cases is separate future work.
